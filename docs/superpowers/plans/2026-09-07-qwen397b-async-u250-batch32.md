# Qwen3.5-397B Async U250 Batch-32 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preserve a strict one-token GPU/U250 correctness oracle, diagnose the current empty handwritten SSE response, and add a fail-closed 32-active asynchronous persistent-U250 performance path for 64 requests times 32 tokens.

**Architecture:** Keep the existing xclbin and 141/39 tensor placement. Split correctness and performance configuration, preserve raw SSE failures, increase per-stream route scratch to 32x10, then refactor the persistent XRT submission into two reusable ticket slots with shared gate/up capture, round-robin four-CU polling, merged DMA ranges, and same-stream batched result publication.

**Tech Stack:** Python 3/pytest HTTP evaluator, Bash runners and static contracts, patched llama.cpp C++/CUDA runtime, Rust ZLUDA/XRT runtime, XRT C API, CUDA Driver API, U250 persistent xclbin.

        evaluator.stream_completion("http://fake", {}, 1, events_path)
