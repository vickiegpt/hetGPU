\title{\sys: A Heterogeneous GPU IR for All}

\author{Anonymous Authors}

\begin{document}

\begin{abstract}
GPUs anchor modern AI infrastructure, yet their software remains trapped in
vendor silos: a binary compiled for one vendor's ISA executes nowhere else,
and emerging spatial hardware is reachable only through entirely separate
synthesis toolchains.  We present \sys, a heterogeneous GPU IR designed to be
lowered everywhere.  \sys compiles CUDA programs once into a single
vendor-neutral IR whose lane-packed mask-SSA micro-operations make SIMT
semantics---active masks, predication, scoped memory, synchronization, and
warp collectives---first-class, so that no lowering path has to recover them.
Four lowering paths hang off this IR: JIT translation to PTX for NVIDIA,
SPIR-V for AMD and Intel, TOSA/TT-MLIR for Tenstorrent's MIMD many-cores, and
static spatialization into \circt circuits whose correctness against the PTX
memory model is stated as a trace-refinement theorem.  A uniform runtime loads
the IR on any backend, virtualizes threads, memory, and synchronization, and
serializes execution state at compiler-identified safe points to live-migrate
running kernels across heterogeneous GPUs.  A prototype executes the same
unmodified GPU binary on NVIDIA H100, AMD RX~9070 XT, Intel Iris Xe, and
Tenstorrent BlackHole with modest overhead, migrates kernels mid-execution
between vendors with seconds of downtime, and a Verilator artifact executes
real PTX-derived instruction streams as explicit RTL uses with zero
mismatches.  \sys shows that one GPU IR can serve every silicon: vendor GPUs
today, spatial fabrics next.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Modern computing runs on GPUs, yet GPU software remains locked to the vendor
that compiled it.  A CUDA binary executes on NVIDIA hardware and nowhere
else: ISAs, execution models, and driver interfaces are incompatible across
NVIDIA, AMD, and Intel, and emerging accelerators such as Tenstorrent's
RISC-V many-cores add a third organization with no warp hardware at
all~\cite{lustig2019ptx,chen2018tvm,lattner2021mlir}.  This lock-in is
becoming more costly along a second axis.  Spatial accelerators---FPGAs,
CGRAs, and dataflow fabrics---replace instruction fetch with circuits whose
behavior is largely fixed at compile time, but their toolchains enter from
the source level through HLS and spatial DSLs
\cite{koeplinger2018spatial,prabhakar2017plasticine,ye2021scalehls}.  The
enormous ecosystem of deployed GPU kernels, distributed as PTX or embedded in
framework JIT caches, is reachable from spatial hardware only after source
recovery, rewriting, or manual porting.  Two silos---vendor silos and
device-type silos---share one root cause: there is no GPU intermediate
representation that any hardware can lower.

Source-level portability layers do not close the gap.  OpenCL, SYCL/oneAPI,
and HIP unify the programming model but still compile per vendor, and they
cannot help binary-only dependencies at all.  The operational cost of
non-portable binaries falls on everyone downstream: teams maintain parallel
builds and divergent debugging workflows; schedulers pin jobs to
vendor-specific pools while other GPUs sit idle; maintenance and failures
force draining jobs rather than moving
them~\cite{xiao2018gandiva,gu2019tiresias,narayanan2020gavel,yu2020salus}.
Cluster schedulers already rely on iteration-level checkpointing to juggle
workloads~\cite{narayanan2020gavel}, but without a portable binary substrate
they cannot treat a heterogeneous fleet as one fungible pool, and
CUDA-on-X translation systems that do exist stop at processor
backends~\cite{huang2023cupbop}.

We present \sys, a heterogeneous GPU IR designed to be lowered everywhere.
\sys compiles CUDA programs once into a single vendor-neutral IR that
captures GPU parallel semantics---thread hierarchies, memory spaces,
barriers---and, crucially, makes SIMT \emph{execution} semantics
first-class: every value is a lane-packed vector paired with an active-lane
mask, and predication, scoped memory ordering, and warp collectives are IR
constructs rather than facts each backend must recover.  Four lowering paths
hang off this IR.  At run time, a JIT translates it to PTX for NVIDIA,
SPIR-V for AMD and Intel, and TOSA/TT-MLIR for Tenstorrent's MIMD cores.  As
a second axis, the same IR-level semantics spatialize into statically
scheduled \circt circuits for spatial hardware: regular regions become fixed
pipelines, and only barriers, atomics, and unresolved memory dependences
become control-token boundaries.  The claim packed into ``for all'' is
precise: one IR, every lowering, and no semantic recovery per target.

Three obstacles stand in the way, and each is answered inside the IR.
First, execution organizations differ: SIMT designs execute lockstep lanes
with implicit reconvergence, Tenstorrent schedules independent cores, and
spatial fabrics fix schedules statically.  The \sys µop layer carries
masks and lane packing explicitly, so each backend maps or emulates SIMT
semantics from the same representation instead of reconstructing it.  Second,
memory and synchronization semantics are uneven across vendors, and PTX's
memory model is weak, scoped, and deliberately not data-race-free---racy
programs still have defined
behaviors~\cite{lustig2019ptx}.  \sys attaches order and scope labels to
every memory operation in the IR and requires each lowering to implement and
be checked against them; for the spatial path this obligation is discharged
by a trace-refinement theorem under an explicit backend memory contract.
Third, portability must extend to execution \emph{state}, not just code, so
that preemption and live migration work across backends with different
grouping granularities; \sys marks safe suspension points in the IR and
defines a device-neutral state representation over virtual registers,
program counters, and active masks.

This paper makes four contributions:
\begin{itemize}
  \item \textbf{The Concordia IR}: a vendor- and hardware-form-agnostic GPU
  IR whose lane-packed mask-SSA µops make SIMT semantics---masks,
  predication, state spaces, scoped memory, synchronization, warp
  collectives---first-class (\S\ref{sec:ir}).
  \item \textbf{Four lowering paths from one IR}: JIT translation to PTX,
  SPIR-V, and TOSA/TT-MLIR on GPU backends, and static-first spatialization
  into \circt with if-converted mask-SSA regions, tokenized fallbacks for
  non-static effects, and a memory planner that separates affine streams
  from tokenized islands (\S\ref{sec:compilation}).
  \item \textbf{Correctness and migration substrate}: a trace-refinement
  theorem for spatialization against the PTX memory model
  (\S\ref{sec:formal}), plus a uniform runtime with cooperative
  checkpointing and device-neutral state serialization enabling live
  migration across vendor GPUs (\S\ref{sec:runtime}).
  \item \textbf{A working prototype}: the same unmodified GPU binary running
  on NVIDIA H100, AMD RX~9070 XT, Intel Iris Xe, and Tenstorrent BlackHole
  with modest overhead; kernels migrated mid-execution between vendors with
  seconds of downtime; and a Verilator artifact executing real PTX-derived
  instruction streams---five kernels plus a 40-trace Qwen corpus---as
  explicit RTL uses with zero mismatches (\S\ref{sec:impl},
  \S\ref{sec:eval}).
\end{itemize}

The remainder of the paper reviews the hardware and portability landscape
(\S\ref{sec:background}), presents the IR (\S\ref{sec:ir}), its compilation
paths (\S\ref{sec:compilation}), and its correctness theory
(\S\ref{sec:formal}), describes the runtime and migration
(\S\ref{sec:runtime}) and prototype (\S\ref{sec:impl}), evaluates the system
(\S\ref{sec:eval}), and discusses related work and limitations
(\S\ref{sec:related}--\S\ref{sec:limitations}).

\section{Background and Motivation}
\label{sec:background}

\subsection{A Landscape of Execution Organizations}
\label{sec:vendors}

GPUs from different vendors share the goal of massively parallel execution
but implement it with different architectural
philosophies~\cite{diamos2010ocelot,huang2023cupbop}.
\textbf{NVIDIA} GPUs organize execution as Streaming Multiprocessors running
warps of 32 lanes in lockstep SIMT, with divergence handled by masking until
reconvergence; CUDA compiles through the PTX virtual ISA to SASS, and memory
is a hierarchy of per-thread registers, CTA-scoped shared memory, and device
global memory whose consistency is ensured at synchronization points.  Since
Volta, independent thread scheduling gives each lane its own program counter,
which eases state capture but remains largely invisible to software.
\textbf{AMD} GPUs are structurally similar: Compute Units schedule wavefronts
(histories of 64 lanes on GCN, 32 on RDNA) in lockstep, with Local Data Share
providing workgroup-scoped scratchpad memory, and code compiled via LLVM
through HIP or OpenCL.  \textbf{Intel} GPUs expose subgroups of 8--32 lanes
through SYCL/oneAPI or OpenCL, consume SPIR-V, and compile through Level
Zero~\cite{spirv,levelzero}; integrated parts share coherent memory with the host, discrete parts do
not.  \textbf{Tenstorrent}'s BlackHole departs from SIMT
totally~\cite{tenstorrent}: it is a
mesh of 120+ independent RISC-V Tensix cores, each with a 32-lane vector
unit, private local memory, and explicit DMA for off-chip traffic.  Running a
CUDA-style kernel on it requires either executing a warp on one core's vector
lanes under explicit masks, or partitioning a block across cores with explicit
inter-core synchronization---an execution-organization bridge any portable
substrate must build.  These four organizations differ in warp width, memory
hierarchy, scope lattices, and scheduling model; they agree, roughly, on the
CUDA programming model's grid/block/thread semantics, which is the level our
IR preserves.

\subsection{PTX as a Structured Binary Interface}
\label{sec:ptx-interface}

PTX is a virtual ISA for parallel thread execution, traditionally consumed by
NVIDIA's driver JIT, but its exposed abstractions are much richer than those
of a scalar processor binary~\cite{nvidia_ptx_isa_93,nvidia_cuda_platform}.
PTX kernels launch over a grid of CTAs; threads are identified through
special registers; and each instruction executes in the context of a lane and,
operationally, a warp.  Named state spaces separate per-thread registers,
CTA-shared memory, thread-local memory, launch parameters, and device global
memory.  Several PTX features matter directly to any consumer of GPU
binaries.  Predication makes if-conversion a native idiom rather than a
recovery pass.  Branch divergence is defined at the SIMT control level, so
inactive lanes must be represented, not silently discarded.  \texttt{bar.sync}
defines CTA-level phase boundaries; \texttt{membar}-style operations define
scoped memory-ordering constraints; \texttt{atom.*} operations emit ordered
read-modify-write events; and warp collectives such as \texttt{shfl.sync}
communicate between lanes under an explicit participant mask.  A consumer
that erases this structure---as LLVM-level lowering tends to do---must later
recover it or get the semantics wrong.

PTX also contains features no compiler should quietly claim to support:
cluster memory, asynchronous bulk-copy families, tensor instructions,
texture/surface legacy spaces, and architecture-dependent
extensions~\cite{nvidia_ptx_isa_93}.  A defensible treatment is a stated
fragment---arithmetic, predication, branches, special-register reads, loads
and stores across the five state spaces, \texttt{bar.sync}, scoped fences,
atomics, and \texttt{shfl.sync}---with unsupported features rejected up
front.  This fragment is small enough to specify and rich enough for common
GPU idioms, and \S\ref{sec:formal} gives it precise semantics.

\subsection{Existing Portability Paths and Why They Fall Short}
\label{sec:existing}

Source-level frameworks unify code, not binaries.  OpenCL and SPIR-V provide
a standard ingest format~\cite{spirv}, but SPIR-V is a static code
representation
targeting driver-side compilation; it encapsulates no execution state and
leaves subgroup mapping vendor-specific.  HIP and SYCL/oneAPI ease
maintaining one source tree, but every placement still compiles per vendor,
and binary-only dependencies do not port.  Virtualization and checkpoint
tools decouple applications from physical devices---rCUDA forwards API calls
to remote GPUs, Cricket checkpoints CUDA via RPC, CRIUgpu dumps driver
state---but all assume NVIDIA hardware on both ends, treating the GPU as a
device to freeze and restore on identical silicon~\cite{kato2012gdev}.
Binary translation systems are closest in spirit: GPU Ocelot JIT-compiled
PTX for non-NVIDIA hardware~\cite{diamos2010ocelot}, and ZLUDA translates
PTX through LLVM for AMD/Intel GPUs~\cite{zluda}; CuPBoP retargets CUDA to
CPU-style parallel runtimes~\cite{huang2023cupbop}.  These systems
demonstrate that PTX can serve as a portable execution interface, but they
translate it to another \emph{processor} runtime: none lower GPU binaries to
spatial hardware, none design the IR to avoid direct-translation pitfalls,
and none couple binary portability with live migration of running state.

The gap is thus twofold.  No existing system provides binary-level
portability across NVIDIA, AMD, Intel, and Tenstorrent with live state
migration; and no system treats PTX-level GPU semantics as a binary-level
interface to spatial hardware.  \sys addresses both from one IR: the
portability substrate of a virtualized GPU binary, with execution semantics
kept explicit enough that a spatial fabric can be just another lowering
target.

\subsection{Design Principles}
\label{sec:ir-principles}

Figure~\ref{fig:sys} shows the stack: a CUDA application (or a captured PTX
module) enters the frontend, becomes CTX, and the IR is lowered by one of
four paths behind a uniform runtime.  The IR is designed around four
principles.  \textbf{Capture GPU semantics,
not vendor syntax.}  A kernel in the IR is an SPMD program over a grid of
CTAs with explicit synchronization, explicit predication, and unified memory
operations; the IR preserves what every vendor implements---grids, blocks,
threads, barriers, state spaces---and abstracts what only one vendor spells a
particular way.  \textbf{Make SIMT execution explicit.}  Every value is a
lane-packed vector paired with an active-lane mask.  Divergence, predication,
and warp collectives are IR constructs, so no lowering path starts from a
representation in which SIMT facts have been lost and must be recovered.
\textbf{Carry memory semantics from the front end.}  State spaces, memory
orders, and scopes are attached to memory operations when the IR is created
and are never erased by optimization; backends consume these labels rather
than re-deriving them from address arithmetic.  \textbf{Expose state, not
just code.}  The IR travels with metadata naming safe suspension points and
mapping IR values to a device-neutral state representation, making
checkpointing and migration runtime capabilities rather than per-backend
reverse-engineering projects.

\subsection{Structure: Lane-Packed Mask-SSA Micro-Operations}
\label{sec:ir-uops}

The IR's value representation has three types,
\[
  \texttt{vec}\langle W,\tau\rangle,\qquad
  \texttt{mask}\langle W\rangle,\qquad
  \texttt{token},
\]
where $W$ is the warp width of the region.  A \emph{compute µop} consumes
lane-packed vectors and a mask and produces a lane-packed vector.  A
\emph{control µop} consumes and produces masks or tokens.  A \emph{memory
µop} carries address space, order, scope, access width, and coalescing
metadata on top of its data operands.  The IR provides explicit nodes for
\texttt{split}, \texttt{merge}, \texttt{barrier}, \texttt{fence},
\texttt{atomic}, \texttt{shuffle}, \texttt{load}, and \texttt{store}; the
only PTX-specific names that survive are semantic attributes such as state
space, scope, and special-register identity.

The representation choice follows from SIMT semantics.  Scalar per-lane SSA
is precise but explodes graph size and hides warp collectives behind dozens
of identical scalar operations; plain lane-packed vector SSA is compact but
cannot represent divergence or inactive lanes.  Lane-packed \emph{mask}-SSA
matches predication, divergence, and \texttt{shfl.sync} directly, at the
cost of precise mask merge/split invariants; where effects must not be
reordered---barriers, fences, ordered atomics, long-latency memory---the IR
adds explicit \texttt{token} values so that scheduling can never move an
effect across its boundary.

The invariant that makes this representation sound is the \emph{mask-value
invariant}: on every live data edge, the value is a pair $(m, v)$ of an
active mask and a lane-packed vector, where for every lane $\ell$ with
$m[\ell]=1$, $v[\ell]$ equals the PTX value held by lane $\ell$ at the
corresponding program point, and for $m[\ell]=0$, $v[\ell]$ is
unconstrained.  A lane outside the mask cannot update a live output, issue a
memory event, or arrive at a barrier.  \S\ref{sec:formal} makes this
invariant precise and builds the correctness theorem on it.

\subsection{The Memory and Synchronization Contract}
\label{sec:ir-memory}

Every memory µop names its state space---\texttt{global},
\texttt{shared}, \texttt{local}, \texttt{const}, or \texttt{param}---as an
address-space attribute rather than a flat pointer, and carries a memory
order in \{$\mathsf{weak}$, $\mathsf{relaxed}$, $\mathsf{acquire}$,
$\mathsf{release}$, $\mathsf{acq\_rel}$, $\mathsf{sc}$\} and a scope in
\{$\mathsf{cta}$, $\mathsf{gpu}$, $\mathsf{sys}$\}.  Barriers are CTA-level
phase events: the IR models arrival and release as separate effects so that
no backend can let a lane pass a barrier its phase has not reached.  Shuffle
µops produce their value vector \emph{and} a validity mask, making the
PTX rule explicit that a shuffle whose source lane is outside the participant
set yields an unconstrained value.

These labels constitute a contract each backend must implement and be
checked against.  On the GPU paths, the labels map onto vendor memory-model
documented behavior (address spaces and scopes for PTX, ROCm, and SPIR-V).
On the spatial path, the labels become events in the refinement theorem's
backend memory contract $B$: a lowering may serialize or delay labeled
effects, but it may not drop or reorder them outside what the PTX memory
model permits.

\subsection{CTX: The Serialized Program Form}
\label{sec:ir-ctx}

The IR ships as \textbf{CTX} (\textbf{C}oncordia \textbf{T}hread
e\textbf{X}ecution), a text assembly form with SSA virtual
registers (an effectively infinite set; backends allocate physical
registers), PTX-like directives, and inline annotations.  Text was chosen for
debuggability and late binding: a CTX module is inspectable, diffable, and
decoupled from any vendor's object format.  Kernels are identified by a
compile-time identifier so the runtime's JIT cache can key translated
artifacts per device (\S\ref{sec:compilation}).  Two kinds of annotation
matter for state.  Every barrier and kernel exit is a labeled \emph{safe
suspension point}; and a DWARF-style map links live virtual registers,
program-counter positions, and active masks to the device-neutral snapshot
representation the runtime checkpoints (\S\ref{sec:runtime}).

\section{Compilation}
\label{sec:compilation}

\subsection{Front End}
\label{sec:frontend}

The \sys compiler is built on LLVM's CUDA toolchain.  Clang's CUDA code
generation is modified to emit device-agnostic LLVM IR: calls that Clang
would normally lower to NVIDIA builtins are remapped to \sys intrinsics
(\texttt{llvm.concordi.barrier}, \texttt{llvm.concordi.ld.shared},
\texttt{llvm.concordi.shfl}, \etc), which carry SIMT and memory semantics
through the optimization pipeline.  A custom LLVM backend, \texttt{CTXTarget},
then emits CTX assembly.  Optimizations at IR level are target-agnostic by
policy: device-independent transformations are welcome, but anything that
assumes hardware characteristics---warp-size-specific unrolling, for
example---is deferred to the per-backend JIT so it can be tuned per device.
The backend also attaches the state annotations of \S\ref{sec:ir-ctx}: safe
suspension points at barriers and exits, and the source-to-IR value map used
for checkpointing.

\subsection{GPU Lowering Paths}
\label{sec:gpu-lowering}

Each GPU backend is a translation module from CTX to the vendor's ingest
format, integrated into the runtime's JIT (\S\ref{sec:jit}); a new vendor is
a new module, not a new compiler.

\paragraph{NVIDIA/PTX.} CTX is converted to an in-memory PTX IR (reusing
NVVM structures where possible), mapping each CTX instruction to one or more
PTX instructions: special-register reads become \texttt{ctaid}/\texttt{tid}
reads, predicated regions become \texttt{@predicate}-guarded instructions or
PTX control flow, and barriers become \texttt{bar.sync}.  The driver's JIT
(\texttt{ptxas} via the CUDA driver API) then produces a cubin, with
\texttt{.target} directives matched to the device's compute capability.

\paragraph{AMD/ROCm.} CTX is converted to SPIR-V using SPIRV-Tools and
compiled through ROCm's stack.  \texttt{LD\_GLOBAL} maps to
\texttt{OpLoad} from \texttt{CrossWorkgroup}; \texttt{LD\_SHARED} maps to
\texttt{Workgroup} storage with a declared workgroup array per kernel;
barriers become \texttt{OpControlBarrier} with workgroup scope.  Predication
requires structure: SPIR-V demands structured merges, so if--else regions
emit \texttt{OpSelectionMerge} and \texttt{OpBranchConditional} with a
single reconvergence point per divergent region.

\paragraph{Intel/Level Zero.} The same SPIR-V path serves Intel through
Level Zero, which compiles SPIR-V to the hardware ISA.

\paragraph{Tenstorrent/TOSA.} CTX is lowered to TOSA MLIR and passed through
Tenstorrent's TT-MLIR pipeline to a device binary.  Registers map to TOSA
tensors (scalars become 0-dimensional tensors, 32-lane vectors become
\texttt{tensor<32xf32>}); an unpredicated \texttt{FADD.F32} becomes
\texttt{tosa.add} over 32-element tensors, and a predicated one becomes
\texttt{tosa.add} under a \texttt{tosa.select}; global memory accesses
become \texttt{tosa.gather}/\texttt{tosa.slice} by indexing pattern; shared
memory uses MLIR memory-space attributes; and synchronization points are
emitted as markers that the Tenstorrent lowering implements on the mesh.

\subsection{Spatial Lowering}
\label{sec:spatial}

The fourth path does not lower to another processor at all: it spatializes
the PTX-level instruction stream into statically scheduled \circt circuits.
The positioning matters.  \sys spatialization is not HLS.  HLS starts from
source whose loops, arrays, and types are still the author's abstractions,
and its correctness target is source behavior after transformation.  The
unit of work here is a PTX instruction under an active lane mask---by the
time a kernel has passed through CUDA, LLVM, NVVM, and \texttt{ptxas}, the
source abstraction is gone, and the compiler's job is to preserve what the
binary-level SIMT program does, not to re-synthesize what a recovered C
program might mean.  Table~\ref{tab:hls-diff} summarizes the contrast; the
correctness target column is the substantive difference, and
\S\ref{sec:formal} discharges it.

Fallback path & Designer rewrites source or adds pragmas. & Compiler cuts
to tokenized memory/control while preserving PTX events. \\
\bottomrule
\end{tabular}
\end{table}

\paragraph{Decoder and normalizer.} The front end of the spatial path parses
PTX, builds a CFG, resolves labels, and converts register and predicate
files to SSA.  Normalization makes four SIMT facts explicit: all predication
becomes a guard input on the µop it controls; special-register reads
(\texttt{\%tid.x}, \texttt{\%laneid}, \texttt{\%ctaid.x}) become pure µops
parameterized by the launch configuration; state spaces are preserved as
address-space attributes; and order/scope labels are attached to every load,
store, atomic, and fence \emph{before} optimization.

\paragraph{Region formation.} The compiler must decide where static
schedules are safe.  Algorithm~\ref{alg:regions} is deliberately
conservative: the CFG is cut at barriers, fences, ordered atomics, calls,
unsupported operations, and unresolved inter-region memory effects, and each
cut component becomes a warp region.  If-conversion of short divergent
diamonds into mask-SSA hyperblocks is cost-driven---favored when both arms
are short and side-effect-free or provably disjoint, avoided when an arm
contains long-latency memory, atomics, barriers, or unspecializable loops.
The semantic point is that the choice is local: either representation must
preserve the same mask-value relation at the region exit.

\begin{algorithm}[t]
\caption{Region formation in the spatial path.}
\label{alg:regions}
\begin{algorithmic}[1]
\STATE Build a PTX CFG after normalization and SSA conversion.
\STATE Cut the CFG at barriers, fences, ordered atomics, calls,
unsupported operations, and unresolved inter-region memory effects.
\FOR{each cut component}
  \STATE Form single-entry/single-exit warp regions.
  \STATE If-convert short divergent diamonds into mask-SSA hyperblocks.
  \STATE Keep large or irregular control as separate mask-token regions.
  \STATE Mark memory-waiting boundaries for tokenized lowering.
\ENDFOR
\STATE Emit region interfaces containing masks, live values, memory
phase, and token dependencies.
\end{algorithmic}
\end{algorithm}

\paragraph{Static-first SIMT scheduling.} The scheduling unit is the
normalized PTX instruction string, not a recovered loop body.  Within a
region, the compiler first preserves the program order each active lane
observes; the initial schedule for a straight-line region is the identity
schedule, which maps every µop to a concrete hardware use---arithmetic slot,
predicate slot, permuter, scratchpad port, load-store issue slot, or token
sequencer.  Optimization is then constrained compaction: two µops may share
a cycle or pipeline only where SSA, predicate, memory-effect, and token
edges allow.  The fallback schedule is therefore already a faithful
hardware spelling of the PTX string, which also gives translation validation
a one-to-one comparison at a fixed granularity.  Masks are part of the
schedule, not a side condition: a scheduled stage has mask inputs, a masked
lane is architecturally silent, and a predicated store depends on its
predicate vector as a real operand.  A \texttt{shfl.sync} becomes one
permuter use over a lane-packed vector and a participant mask---producing a
value vector and a validity mask---rather than 32 scalarized lane
controllers.

\paragraph{Token islands.} Effects that must not be pretended static are
isolated behind a small interface,
\[
  (m, v_0,\ldots,v_k, t_{in}) \rightarrow
  (m', v'_0,\ldots,v'_j, t_{out}, E),
\]
where $E$ is the ordered summary of memory or synchronization events the
island emits.  An island may take many target cycles but occupies a single
source position in the region schedule.  Atomics are the simplest island: a
backend without a matching scoped atomic serializes enabled lanes in a
deterministic order, choosing one interleaving from the PTX behavior set
rather than inventing a new one.  Barriers are islands with participant
accounting: an epoch register, arrival bits, and a release condition that
fires only when every required non-exited participant has arrived in the
current phase.  Indexed or data-dependent memory is a third island: address
computation stays lane-packed, but the sequencer emits per-lane events
behind the token interface.

\paragraph{CIRCT lowering.} Straight-line and regular pipelined regions
lower to \texttt{pipeline.scheduled}; controllers, barriers, atomics,
scratchpads, and loops needing non-unit initiation intervals lower directly
to \texttt{hw}/\texttt{comb}/\texttt{seq}; irregular memory islands may
lower through \texttt{handshake} or \texttt{dc}.  Table~\ref{tab:circt}
summarizes the routes and their risks.  The division also serves
validation: scheduled compute regions check by combinational or bounded
equivalence after stage alignment, while barrier and FIFO controllers check
better as bounded protocol properties.

\subsection{MemoryPlan: Static Streams vs.\ Tokenized Memory}
\label{sec:memoryplan}

Spatial efficiency normally wants address generators and stream FSMs, while
PTX exposes per-thread address arithmetic.  \sys therefore treats streaming
as a validated optimization, not the default memory lowering.  After
lifting and region formation, a MemoryPlan groups memory events per region.
A group becomes a static affine stream only when its address expression is a
base plus an affine function of launch-specialized symbols---\texttt{\%tid},
\texttt{\%ctaid}, lane id, loop induction, parameters, constants---and then
lowers to an address-generation FSM plus a ready/valid path, with the proof
obligation that emitted stream addresses, masks, kinds, orders, and scopes
equal the source µop's memory events for every active lane.  Groups with
dynamic inner indices (row pointers, gathers) become hybrid indexed streams:
spatial phase controller, tokenized memory island.  If address recovery,
alias checks, or ordering checks fail, the group stays opaque token memory.
This matters for real workloads: captured Qwen prefill kernels contain
regular outer control over non-affine inner indexing, and MemoryPlan is what
keeps them compilable without pretending their memory is uniform.

\subsection{JIT Specialization and Caching}
\label{sec:jit}

All four paths share one specialization discipline.  The JIT specializes on
launch geometry, dynamic shared-memory size, constant kernel arguments,
subgroup width, and backend resource profile, keyed by
\[
\kappa =
(\mathrm{hash}(K),\lambda,\eta,H,\mathrm{PTXVersion},
\mathrm{LLVM/CIRCTRevision}).
\]
Cold compilation runs decode, region formation (spatial path), scheduling,
lowering, and validation; warm execution reuses the compiled artifact and
replays only launch-time parameterization.  Version pinning is part of the
key because PTX, NVVM IR, LLVM backends, and \circt dialects all evolve.
For NVIDIA targets the runtime may also carry a native cubin in the CTX
module as a fat-binary fallback, though the prototype relies on
translation.

\section{Formal Correctness}
\label{sec:formal}

The refinement theorem of this section grounds the spatial path of
\S\ref{sec:spatial}: every externally visible behavior of the emitted
circuit must be a legal PTX behavior of the source kernel.  The GPU JIT
paths are held to the same functional standard by differential testing
against vendor baselines (\S\ref{sec:eval}).  The intent here is not to
formalize all of PTX but to define a fragment precise enough for the theorem
and small enough for translation validation.

\subsection{Source Fragment}
\label{sec:fragment}

Figure~\ref{fig:ptx-core} sketches the PTX core.  It contains scalar integer
and floating-point types, predicates, the five named address spaces, scoped
memory orderings, predicated instructions, branches, barriers, fences,
atomics, and warp shuffles.  It excludes tensor instructions, textures and
surfaces, dynamic parallelism, cluster-scope operations, asynchronous copy
families, inline target assembly, and driver-defined environment registers.

\begin{lstlisting}

as   ::= global | shared | local | const | param
ord  ::= weak | relaxed | acquire | release | acq_rel | sc
scp  ::= cta | gpu | sys

i ::= mov x, y
    | ld.as.ord.scp x, [a]
    | st.as.ord.scp [a], x
    | atom.as.op.ord.scp x, [a], y

    | selp x, y, z, q

    | membar.scp

\end{lstlisting}

The well-formedness judgment rejects unsupported features and PTX undefined
behaviors that would make the theorem vacuous: every dynamic
\texttt{bar.sync} instance must be reached convergently by its participating
non-exited threads; a shuffle source lane must be active whenever the
returned value is used without checking the validity predicate; and
address-space casts must preserve state-space provenance.

\subsection{Source Semantics}
\label{sec:source-sem}

For a CTA, the source machine state is
\[
  \Sigma =
  \langle
    M_g, M_s,
    M_l,
    (R_\ell,P_\ell,pc_\ell,alive_\ell)_{\ell<|T|},
    \mathsf{Bar},
    \mathsf{WarpCtl}
  \rangle ,
\]
with $M_g$ global memory, $M_s$ CTA shared memory, $M_l$ per-thread local
memory, per-lane register/predicate files $R_\ell, P_\ell$, program counters
$pc_\ell$, liveness flags $alive_\ell$, barrier phase state $\mathsf{Bar}$,
and per-warp active masks and reconvergence stacks $\mathsf{WarpCtl}$.
Parameter and constant spaces are immutable launch-supplied maps.  The
transition relation
$K,\lambda \vdash \Sigma \xrightarrow{\alpha} \Sigma'$
executes the instruction at a warp's active program counter; $\alpha$ is
either silent, a vector of memory events, or a control event (barrier
arrival, exit).  Let $A_w$ be warp $w$'s active mask; a predicated
instruction $@p\,i$ has enabled lanes
$E = \{\ell \in A_w \mid alive_\ell \wedge P_\ell(p)=1\}$, and lanes in
$A_w \setminus E$ advance without changing destination state.

Memory instructions emit events
$e = \langle \mathit{cta}, \mathit{tid}, \mathit{kind}, \mathit{as},
\mathit{addr}, \mathit{val}, \mathit{ord}, \mathit{scope} \rangle$, and
$\mathrm{Obs}_{\mathrm{PTX}}(K,\lambda)$ is the set of event traces
consistent with PTX control semantics and the PTX memory axioms.  The
event-trace view is required because PTX is weakly ordered and scoped and
does not require data-race freedom for a program to have
meaning~\cite{lustig2019ptxmemory}.

Two rules illustrate the style.  Arithmetic and moves are lane-wise:
\[
\frac{
  i = x \leftarrow f(y_1,\ldots,y_k)
  \qquad
  v_\ell = f(R_\ell(y_1),\ldots,R_\ell(y_k))
}{
  K,\lambda \vdash \Sigma
  \xrightarrow{\epsilon}
  \Sigma[
    R_\ell(x) := v_\ell,\ pc_\ell := pc_\ell+1
  ]_{\ell\in E}
}
\]
with predicate-disabled lanes leaving state unchanged, and lanes outside
$A_w$ suspended until their reconvergence frame resumes.  Loads emit one
read event per enabled lane and constrain the loaded value to one allowed by
the PTX memory model:
\[
\frac{
  a_\ell = R_\ell(a)
  \qquad
  e_\ell=\langle cta,tid_\ell,\mathsf{rd},as,a_\ell,v_\ell,ord,scp\rangle
}{
  K,\lambda \vdash \Sigma
  \xrightarrow{(e_\ell)_{\ell\in E}}
  \Sigma[R_\ell(x):=v_\ell,\ pc_\ell:=pc_\ell+1]_{\ell\in E}
}
\]
Stores and atomics are analogous (write and read-modify-write events per
enabled lane, the atomic's old value written to the destination); fences
emit scope-labelled fence events and change no registers.  Divergent
branches partition $A_w$ into taken and fall-through masks under a
reconvergence frame, in either order, preserving per-lane program order.
\texttt{shfl.sync}, \texttt{vote}, and \texttt{redux.sync} operate on the
intersection of $A_w$, the member mask, and non-exited lanes; a shuffle
whose source lane is outside the participant set yields an unconstrained
value with a false validity predicate, and well-formed programs use such a
value only under that predicate.  \texttt{bar.sync} is a CTA phase rule:
lanes record the current barrier epoch in $\mathsf{Bar}[b]$ and block; the
barrier releases only when the required participants for that dynamic
instance have arrived in the same epoch.  \texttt{exit} clears
$alive_\ell$.

\subsection{The µop Machine and the Target Circuit}
\label{sec:uop-sem}

The IR-side state mirrors the source but over explicit masks and tokens:
\[
  \Omega =
  \langle
    V, M_g, M_s, M_l, \mathsf{Tok}, \mathsf{BarT},
    \mathsf{Ready}, cycle
  \rangle ,
\]
where $V$ maps each µop result to a pair $(m,v)$ obeying the mask-value
invariant of \S\ref{sec:ir-uops}.  A pure µop fires when its data,
predicate, memory, and control dependencies are in $\mathsf{Ready}$,
evaluates its mask and value lane-wise, and leaves lanes outside its mask as
dead-lane don't-cares.  Memory µops emit the same event kind, state space,
order, and scope as their source rules; atomics and fences are hard region
cuts, so no schedule may move memory effects across them without an explicit
dependency.  Shuffle and collective µops use the same participant-set rule
as the source machine over the explicit input mask, and barrier µops inherit
the epoch discipline of $\mathsf{Bar}$ through $\mathsf{BarT}$: no token
leaves a barrier region until the dynamic participant count for the epoch
has arrived.  Control µops update tokens and masks; a short branch may be
represented either as mask-SSA select/merge or as tokenized control, and
both must produce the same exit mask and live values.

The target is a synchronous transition system
$C = \langle S_C, I_C, O_C, \delta_C, \lambda_C \rangle$ whose state
comprises pipeline and mask registers, control-token state, barrier
counters, pending memory transactions, and scratchpads.  Each compiled
region is a µop graph
$G_r = (U_r, E_r^{data} \cup E_r^{ctrl} \cup E_r^{mem})$ with schedule
$\sigma_r : U_r \rightarrow \mathbb{N}$ and placement
$\pi_r : U_r \rightarrow R_H$ subject to dependence constraints
($\sigma_r(v)-\sigma_r(u) \geq \mathrm{lat}(u)$ for every edge
$u \rightarrow v$) and resource constraints
($|\{u \mid \pi_r(u)=q \wedge \sigma_r(u)=t\}| \leq \mathrm{cap}(q)$).
Static scheduling does not require compile-time completion cycles:
scheduled regions stall on memory backpressure or token boundaries, and
stalls are stuttering steps.

\subsection{Correctness}
\label{sec:correctness}

The simulation relation is built on the mask-value invariant: masked lanes
carry PTX values, unmasked lanes are unconstrained, and unconstrained
components cannot influence subsequent well-formed instructions because
later uses are masked by the reconverged active mask.

\begin{lemma}[Mask-$\phi$]
\label{lem:maskphi}
Suppose a branch splits mask $m$ into disjoint masks $m_1$ and $m_2$,
computes $x_1$ under $m_1$ and $x_2$ under $m_2$, and emits
$x = \mathrm{merge}(m_1:x_1,m_2:x_2)$.  For every live lane $\ell$,
$x[\ell]$ equals the PTX value selected at the reconvergence point.
\end{lemma}

\begin{theorem}[Trace refinement]
\label{thm:refinement}
Let $K$ be a well-defined kernel in the supported fragment, $\lambda$ a
legal launch, $\eta$ a specialization environment, $H$ a spatial backend
profile, and $B$ a backend memory contract.  Assume:
\begin{enumerate}
  \item $K$ contains no unsupported PTX feature.
  \item $K$ does not execute a fragment-excluded undefined behavior.
  \item Register, predicate, and memory alias analyses are conservative.
  \item $B$ preserves the order and scope labels of emitted atomic and
  fence events.
  \item CTA scheduling by the runtime is fair.
\end{enumerate}
If $C=\mathcal{T}(K,\lambda,\eta,H,B)$, then
\[
  \pi(\mathrm{Traces}(C)) \subseteq
  \mathrm{Obs}_{\mathrm{PTX}}(K,\lambda),
\]
where $\pi$ erases cycle counts, ready/valid handshakes, internal tokens,
and other non-observable circuit details.
\end{theorem}

\noindent
The proof is a forward simulation up to stuttering.  Lifting maps each
source rule to a µop rule with the same enabled mask, value update, and
memory-event label; region formation cuts at barriers, fences, atomics,
calls, and unsupported operations, so local transformations cannot cross
semantic phase boundaries; static scheduling preserves the partial order of
data, control, and memory dependences, and scheduled stalls are stuttering
steps erased by $\pi$.  Barrier templates preserve phase separation because
a token cannot leave a barrier until the required participants have arrived
in the current phase; atomics and fences preserve PTX event labels by
assumption $B$; and conservative alias edges may serialize legal PTX
behaviors but cannot introduce illegal ones.  Replicating or
time-multiplexing CTA engines corresponds to choosing one legal CTA
interleaving.

\begin{corollary}[Deterministic kernels]
\label{cor:deterministic}
If $K$ is deterministic under the PTX memory model---for example because it
is single-CTA, or scope-race-free with explicit synchronization---then $C$
and $K$ produce identical final host-visible memory states and kernel
outputs.
\end{corollary}

The corollary is the user-facing result for common GPU kernels.  The general
theorem remains a refinement because PTX gives meaning to racy programs and
because a conservative spatial compiler may deliberately choose a subset of
legal source interleavings.

\section{Runtime and Live Migration}
\label{sec:runtime}

\subsection{Device Abstraction and Launch}
\label{sec:runtime-abstraction}

The runtime is a library, \texttt{libconcordi.so}, exposing a CUDA-shaped
API.  It discovers devices by PCI scan or configuration (Tenstorrent boards
may not appear on a PCI scan) and loads vendor libraries dynamically
(\texttt{dlopen} of \texttt{libcuda.so}, ROCm's \texttt{libhip}, OpenCL, or
Level Zero), so no vendor is a hard dependency.  When
\texttt{concordiLaunchKernel} is called, the runtime looks the kernel up by
its compile-time identifier, JIT-compiles it for the current device if not
cached (\S\ref{sec:jit}), and enqueues it: on NVIDIA/AMD/Intel through the
device's stream or queue; on Tenstorrent through a core pool---allocating
cores for the launch's blocks, loading instruction memory, triggering start,
and polling a completion flag.  Memory allocations
(\texttt{concordiMalloc}) wrap the vendor allocator and tag each device
pointer with its owning device, keeping a pinned host mirror to make
cross-device copies cheap if a buffer is later used elsewhere.

\subsection{Cooperative Checkpointing}
\label{sec:checkpoint}

Migration needs a snapshot of running state.  Rather than relying on
vendor-specific preemption, the runtime and compiler cooperate at the safe
suspension points the IR already labels (\S\ref{sec:ir-ctx}).  The state
representation is device-neutral: per-thread virtual-register files for
every thread in a block, per-thread or per-warp program counters (a single
PC where threads are uniform), active-mask metadata per warp, and a copy of
shared-memory contents.

Capture is two-phase.  First, the runtime sets a \texttt{pause\_flag} for
the target stream's kernels---a global-memory symbol on NVIDIA, an
equivalent device buffer on AMD/Intel, a polled memory flag on
Tenstorrent---so that after the next barrier no new work starts.  Second,
compiler-injected checks at each safe point test the flag; when set, a
thread block copies its live virtual registers and PCs to a global buffer
and exits.  Because all threads must reach the barrier anyway, the snapshot
is automatically race-free at block granularity: either all threads of a
block arrive and dump, or the block has not reached a safe point yet.
\texttt{concordiCheckpoint} then composes the per-block blobs with a copy of
global memory into a state object on the host.

Restore inverts the process.  \texttt{concordiRestore(state, device)}
allocates blocks on the target device, launches a resume kernel, and
reconstructs registers through shared memory on SIMT GPUs: thread~0 copies
the saved register file into shared memory,
\texttt{\_\_syncthreads()}, and each thread loads its own values---the
only portable channel into per-thread registers on hardware that disallows
register initialization at launch.  Shared-memory contents are restored the
same way.  Resuming mid-kernel uses the IR's labeled points: potential
resume positions carry segment IDs, and the resume kernel switches on the
passed ID to jump to the saved basic block.  On Tenstorrent, an assembly
prologue loads vector and scalar register files directly from memory.

The compiler also segments persistent kernels: a global barrier every $X$
iterations turns a long-running kernel into a chain of standard launches
whose boundary state is exactly a snapshot.  Migration then ends the current
segment early on the source device and starts the next segment on the
destination, using the snapshot as input.  This trades generality---pausing
at an arbitrary instruction is not supported---for reliability: no
arbitrary PC mapping across ISAs is ever required.

\subsection{Migration Protocol and Limits}
\label{sec:migration}

Moving a kernel from device A to device B transfers the state object and
global memory (device-to-host-to-device, or peer-to-peer where available),
allocates equivalent buffers, fixes up base addresses, and re-derives the
destination's JIT cache entry.  Data movement dominates downtime; the
protocol's cost is bounded by memory footprint, not kernel complexity
(\S\ref{sec:eval-migration}).  Instrumentation is enabled only when a
checkpoint is planned---barrier-flag checks are cheap, but always-on
instrumentation is not---so surprise preemption is out of scope today; a
hardware-supported pause would remove this limit.  Migration targets GPU
backends; extending state serialization to spatial circuits is future work
(\S\ref{sec:limitations}).

\section{Implementation}
\label{sec:impl}

The prototype targets four platforms: an NVIDIA H100 (Hopper, 96\,GB), an
AMD Radeon RX~9070 XT (RDNA4, 16\,GB), Intel Iris Xe (Xe-LPG, 512\,MB), and
a Tenstorrent BlackHole dev board with 120 Tensix cores (32\,GB), on Ubuntu
24.04 hosts.  The compiler extends LLVM~22; the runtime is
\texttt{libconcordi.so}; the \texttt{CTXTarget} backend and the four
translation modules of \S\ref{sec:compilation} are integrated into the
runtime's JIT.  The spatial path is implemented as a pass pipeline over the
same IR: the PTXSpatial pass defines the mask-aware µop data structures,
region strategies, and proof obligations; the memory planner separates
static affine streams from tokenized groups; and the packaging bridge emits
runtime metadata, CXL shell metadata, RTL, and a generated Verilator
testbench.

The paper's spatial artifact distills that pipeline into a self-contained
RTL core and testbench rather than requiring the full workspace build,
which pulls in LLVM/CUDA/Level-Zero platform tooling.  It keeps the same
conceptual stages---PTX input, SIMT-aware normalization, an ordered use
sequence, lane-packed RTL state, token boundaries---and comprises two
executable flows: a \emph{semantic RTL slice} (five PTX scenarios executed
on an instruction-ROM RTL core with mask-guarded updates, checked against
deterministic PTX oracles) and an \emph{LLM trace route} (40 real Qwen
Triton-cache PTX traces classified structurally, emitted as CIRCT FIRRTL,
lowered with \texttt{firtool}, and simulated under Verilator).  All
evaluation scripts write JSON as the source of truth and derive Markdown
and \LaTeX{} tables from it, recording tool versions and command lines
beside the results, so every table in \S\ref{sec:eval} can be regenerated
rather than hand-entered.

\section{Evaluation}
\label{sec:eval}

We evaluate along five dimensions: functional portability, performance
overhead relative to native, real-world workloads, live migration, and the
spatial path's executable evidence.  Experiments ran on Linux hosts with an
Intel Xeon CPU and four GPUs: NVIDIA H100 (96\,GB), AMD RX~9070 XT (16\,GB),
Intel Iris Xe (512\,MB), and Tenstorrent BlackHole (32\,GB), using CUDA~12,
ROCm~6.4.1, Intel oneAPI Level Zero~1.6, and Tenstorrent tt-metal v0.58.0.
Kernels use default optimizations with migration support off for pure
performance runs; baselines are native toolchains (CUDA via
\texttt{nvcc}, HIP via \texttt{hipcc}, hand-written Level Zero, optimized
Metalium).

\subsection{Portability and Correctness}
\label{sec:eval-portability}

A single CTX binary with a ten-kernel suite---including vector addition,
SAXPY, tiled ($16\times16$ shared-memory tiles) matrix multiplication,
reduction, inclusive scan with warp shuffle, warp-vote bitcount, Monte Carlo
$\pi$ with divergence and atomics, and a small neural-network layer---runs
unmodified on all four platforms with outputs matching known-correct
references.  Two kernels exercised emulation paths:
the scan's shuffle used a \texttt{VOTE\_ANY}-based loop where
\texttt{SHUFFLE} was not yet implemented, and \texttt{atomicAdd} on
Tenstorrent used a global-memory spin lock.  Compiling from CUDA source and
executing on AMD required no AMD-specific code and no \texttt{hipcc}
invocation.  OpenCL C input is future work.

reaches $\sim$80\% of its hand-optimized kernel.  Reduction (1\,M):
0.16\,ms vs.\ 0.17\,ms (NVIDIA), 0.18\,ms vs.\
0.20\,ms (AMD), 0.71\,ms vs.\ 0.73\,ms (Intel), 1.4\,ms (Tenstorrent)---
overheads of 5--15\%.  The divergent Monte Carlo $\pi$ kernel shows the
execution-organization bridge at work: on Tenstorrent, independent-thread
(MIMD) mode across 120 cores reaches $\sim$25\,M points/s while vectorized
warp mode reaches $\sim$18\,M, so the runtime's per-kernel mode selection
matters for irregular kernels.  Elsewhere the overhead is 1.3\% on NVIDIA
($\sim$150\,M vs.\ 148\,M points/s), $\sim$4\% on AMD (140\,M vs.\ 135\,M),
and on Intel \sys reaches $\sim$25\,M points/s against 10\,M for the native
OpenCL baseline, whose divergent-kernel path underperforms here.

First-execution JIT translation takes 50--100\,ms for nontrivial kernels
on NVIDIA (PTX$\rightarrow$SASS via \texttt{ptxas}), 100--200\,ms on AMD
(LLVM$\rightarrow$GCN), $\sim$80\,ms on Intel (SPIR-V), and $\sim$30\,ms on
Tenstorrent (TT-MLIR), as Figure~\ref{fig:jit} shows---acceptable for
long-running programs and amortizable by precompilation.  The abstraction layer adds
negligible overhead to memory operations (microseconds on synchronous
calls).

\subsection{Use Case: Cross-GPU Live Migration}
\label{sec:eval-migration}

We live-migrate a long-running iterative tiled matmul squaring a
$16\,384 \times 16\,384$ matrix: H100 $\rightarrow$ RX~9070 XT
$\rightarrow$ BlackHole.  Checkpointing at an iteration boundary took
$\sim$0.5\,s (2\,GB of matrix data to host over PCIe); restore on the AMD

took $\sim$1.1\,s.  Total downtime was $\sim$2.2\,s in a $\sim$30\,s job,

All five scenarios complete with zero mismatches.  The static lane-packed

static PTX regions are directly representable as ordered use sequences;

correct by tokenization, with their cost visible as token waits.

\subsection{Correctness Checks and Differential Execution}
\label{sec:eval-correctness}

The Verilator harness checks deterministic final outputs, and the structure
of the checks mirrors Theorem~\ref{thm:refinement}: a source-side PTX/SIMT
oracle in the testbench computes expected values per active lane, and the
observable projection covers final checksums, memory-event counts, write
counts, token waits, and valid masks---cycle counts are reported but never
used as an equivalence condition.  Shuffle equality is guarded by the
validity mask, matching the PTX rule for invalid source lanes; the barrier
check verifies that a barrier token delays release and that post-barrier
stores are not emitted early; atomics and indexed memory verify the
conservative-token principle.  The artifact is a bounded executable witness,
not a replacement for translation validation of arbitrary regions.  In a
full build, every scheduled region should emit source-side µop and
target-side circuit formulas for region-local LEC through CIRCT's
\texttt{verif} infrastructure, with bounded model checking for
protocol-heavy subcircuits (barrier epoch advance, FIFO no-drop/no-duplicate,
atomic one-return-per-operation).  The longer-term plan is differential
execution against four baselines: native NVIDIA via NVVM/NVPTX, native AMD
via ROCDL/AMDGPU where a source baseline exists, a portable SPIR-V path
where the fragment is representable, and a PTX interpreter oracle such as
Ocelot for binary-only cases---integer outputs exact, floating point under
documented tolerance, and racy kernels compared against the source behavior
set rather than one interleaving.

\section{Related Work}
\label{sec:related}

\paragraph{GPU virtualization and API emulation.} rCUDA and VirtualCL
forward API calls to remote or virtualized
GPUs~\cite{pavlidakis2024scale,kato2012gdev}; gVirt virtualizes at the
device level~\cite{gvim}; Cricket checkpoints CUDA applications via RPC.
All assume NVIDIA hardware on both ends and stop short of translating
execution to different architectures.  \sys generalizes the virtual GPU
beyond a single vendor, and beyond GPUs to spatial fabrics.

\paragraph{Binary translation and cross-ISA execution.} GPU Ocelot
JIT-compiled PTX for non-NVIDIA hardware~\cite{diamos2010ocelot}; ZLUDA
translates PTX through LLVM for AMD/Intel~\cite{zluda,janik_zluda}; CuPBoP
retargets CUDA to CPU-style runtimes~\cite{huang2023cupbop}.  These systems
demonstrate PTX's viability as a portable execution interface, and their
coverage difficulties motivated designing an IR rather than translating
PTX directly.  \sys differs in target and obligation: lowerings go to
vendor GPU ISAs and to spatial circuits, correctness on the spatial path is
stated against a PTX semantics, and live execution state is part of the
contract.

\paragraph{Portable IRs and compilers.} SPIR-V provides vendor-neutral
ingest but no execution-state story; HSAIL saw limited adoption;
SYCL/oneAPI compiles per target.  TVM and MLIR are compiler
infrastructures, not runtimes~\cite{chen2018tvm,lattner2021mlir}: MLIR's
GPU, NVVM, and ROCDL dialects model launch structure, thread/block IDs,
barriers, and subgroup operations~\cite{mlir_gpu_dialect,
mlir_nvvm_dialect,mlir_rocdl_dialect}, and \sys builds on that
infrastructure---but neither ships a binary that runs across vendors or
spatializes to hardware.  \sys's CTX offers GPU-level semantics (barriers,
masks, thread indices, scopes) that LLVM IR does not carry, and couples
them to a runtime.

\paragraph{Spatial and HLS compilers.} Warp processing translated hot
binary regions into FPGA circuits for scalar programs~\cite{vahid2008warp};
Plasticine and Spatial demonstrate spatial architectures and
hardware-centric source abstractions~\cite{prabhakar2017plasticine,
koeplinger2018spatial}; ScaleHLS organizes HLS optimization in
MLIR~\cite{ye2021scalehls}; DASS and Dynamatic explore the
static/dynamic scheduling trade-off~\cite{cheng2022dass,
josipovic2020dynamatic}.  \sys borrows the hybrid-scheduling lesson but
changes the input level: PTX binaries rather than C/C++, DSLs, or high-level
MLIR, with SIMT masks as first-class schedule inputs
(\S\ref{sec:spatial}).  Research on warp emulation for non-SIMT
hardware~\cite{bauer2014singe,wang2019ffgs} informs the execution-organization
bridge.

\paragraph{GPU semantics and verification.} Lustig et al.'s PTX memory-model
analysis is the basis for treating PTX as a weak, scoped, non-DRF-only
model~\cite{lustig2019ptxmemory}; GPUVerify checks source-level CUDA/OpenCL
properties~\cite{donaldson2014gpuverify}; K-CIRCT demonstrates executable
formal semantics for CIRCT subsets~\cite{zhao2024kcirct}; and CIRCT's
\texttt{verif}/\texttt{smt} dialects, LEC, and BMC make region-wise
translation validation practical~\cite{circt_verif,circt_tools,circt_bmc,
circt_smt}.

\paragraph{Checkpoint/restart and heterogeneous scheduling.} CRIUgpu and
Cricket capture GPU state but restore only on identical
hardware~\cite{lee2019gpusnapshot,nukada2023checkpoint}; cluster schedulers
(Gandiva, Tiresias, Salus, Gavel) preempt at iteration boundaries within
single-vendor pools~\cite{xiao2018gandiva,gu2019tiresias,yu2020salus,
narayanan2020gavel}.  \sys's barrier-segment checkpointing with a
device-neutral state representation enables cross-architecture restore,
turning scheduler placement policies into live-migration operations.

\section{Limitations and Future Work}
\label{sec:limitations}

\sys is fragment-based.  The correctness theorem excludes tensor-core
instructions, asynchronous bulk copy, cluster-scope synchronization,
textures and surfaces, dynamic parallelism, and inline target assembly, and
it does not claim cycle accuracy against NVIDIA arbitration or preservation
of every legal interleaving for racy programs---conservative alias analysis
and atomic sequencing intentionally serialize legal behaviors.  On the
systems side, checkpointing is cooperative (surprise preemption needs
always-on instrumentation), migration data movement dominates downtime, the
IR currently leaves vendor-specific features such as tensor cores
unexploited, and migration targets GPU backends only: extending the same
mask-SSA state serialization across spatial backends is the natural next
step, since the front-end obligations largely coincide.  The spatial
evidence is Verilator-level, not place-and-route; the Qwen corpus is a
deterministic 40-trace sample, and the right future metric is end-to-end
runtime coverage of accepted traces under a fixed serving configuration.
Future work follows directly: tensor instructions and cluster barriers in
the fragment; profile-guided region cloning; a mechanized µop semantics in
the K-CIRCT style~\cite{zhao2024kcirct}; board-level memory-order validation
on the CXL Type-2 shell, draining observed memory-command traces and
checking them against the expected refinement edges; pre-copy and
peer-to-peer migration paths; and hardware pause support to make
checkpointing non-cooperative.

\section{Conclusion}
\label{sec:conclusion}

We presented \sys, a heterogeneous GPU IR designed to be lowered everywhere.
Its lane-packed mask-SSA µops make SIMT execution semantics explicit once,
so that a CUDA program compiled a single time can be JIT-translated to PTX,
SPIR-V, or TOSA/TT-MLIR on NVIDIA, AMD, Intel, and Tenstorrent hardware,
spatialized into statically scheduled \circt circuits under a
trace-refinement guarantee, and migrated between backends mid-execution by
a runtime that checkpoints device-neutral state at compiler-identified safe
points.  The prototype runs unmodified binaries across all four vendor
platforms with modest overhead, migrates kernels with seconds of downtime,
and its spatial path is witnessed by a Verilator artifact executing real
PTX instruction streams---five kernels and a 40-trace Qwen corpus---with
zero mismatches.  One IR, every lowering: vendor GPUs today, spatial
fabrics next.
